# Accessibility report

## When to use

- User asks for an accessibility report, summary, or write-up of findings
- After `/lexable-audit` or `/lexable-review` when a durable report is needed

## Required sections

1. Summary — counts only of issues actually found. State that this is not a conformance claim.
2. Detected issues — severity, WCAG criterion (if supported), file, remediation, verification type.
3. Potential issues
4. Not tested
5. Manual review required
6. Entitlement / mode note — if development mock or unauthenticated, say so. If `advanced.report` / Lexable cloud reports are requested, run `lexable_remote_scan` / status and report `REQUIRES LEXABLE BACKEND` instead of inventing a cloud report.

Do not include a "compliant" or "passed WCAG" section.

## Cloud reports

Advanced Lexable-hosted reports are not generated by this plugin. They require a Lexable API that is not wired. Say so.
